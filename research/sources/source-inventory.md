## Inventory conventions

- Existing detailed-packet source IDs are retained whenever they identify one source cleanly.
- When A1 and a later packet assigned different IDs to the same source, the later detailed-packet ID is the proposed stable ID and the A1 ID is preserved in the alias register.
- A few original research answers cited multiple records under one packet ID. Where the chat did not expose enough metadata to identify each record safely, the source remains a clearly labeled **source set** with every known citation handle retained. Splitting those handles into invented titles would create false bibliography.
- `Primary` means the source is an original/contemporary record or official proceeding. A transcription or index derived from such a record is labeled `primary-derived`, not treated as the original.
- `Secondary` includes obituaries, public biographies, histories, compiled family trees, and research syntheses. `Family-provided` is separate from both.
- Inspection status distinguishes the page or transcription actually consulted from its underlying original. `Underlying not inspected` means the project saw only an index, transcription, search result, compiled profile, or later reference.
- Exact URL fields say `not exposed` when the source chat preserved only an internal `turn…` handle. No URL, publication date, jurisdiction, volume, page, or repository is guessed.
